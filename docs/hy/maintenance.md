# Սպասարկում

[English](../en/maintenance.md) | **Հայերեն** | [Русский](../ru/maintenance.md)

## Պարբերական թարմացում

Նոր մեքենայի վրա նախ վերականգնեք վերջին պատկերի հումքային տվյալները (ավարտված տարիների պայմանագրերի էջերն այդ դեպքում
կրկին չեն ներբեռնվում).

```bash
make install download-raw
```

Այնուհետև.

```bash
make catalog fetch contracts build docs test
git add -A && git commit -m "data: update to $(date +%F)" && git push
make release            # a new data-<collection date> release with the database, Parquet and raw data
```

* `catalog`-ը կարդում է սկզբնական էջը և յուրաքանչյուր հաշվետվության ձևը յուրաքանչյուր տարվա համար. տարիներ,
  դասակարգիչների ցուցակներ՝ կոդերով, PDF փաստաթղթեր (`data/catalog/site.json`, `data/catalog/classifiers/*.json`,
  `data/catalog/documents.json`)։ Փոփոխությունները երևում են `git diff`-ում — հարմար եղանակ՝ նկատելու, որ կայքում ինչ-որ բան
  փոխվել է։ Քայլը նաև ստուգում է, որ «խմբավորել ըստ» տարբերակները դեռ ունեն ակնկալվող պիտակները (`warnings`
  `site.json`-ում)։
* `fetch`-ը կատարում է հաշվետվության յուրաքանչյուր հարցում յուրաքանչյուր տարվա համար (տարեկան ≈15 հարցում + ստուգիչ
  հարցումներ, ընդհանուր 10–30 րոպե. ծախսերի ամբողջական ծառը տևում է մինչև 5 րոպե)։ Ստուգիչ հարցումները կրկին
  կատարվում են իրենց ծառի հետ, քանի որ համադրվում են ըստ գումարների։ Կարելի է նեղացնել՝
  `python -m arm_budget fetch --report revenue --years 2026`։
* `contracts`-ը ներբեռնում է պայմանագրեր ունեցող յուրաքանչյուր ծախսային տողի պայմանագրերի էջը (տարեկան
  ≈2 000–2 300. մեծ մասը ≈1 վ, հազարավոր պայմանագրեր ունեցող տողերի էջերը՝ րոպեներ. երեք տարվա համար ≈3–5 ժամ)։
  Սկավառակի վրա արդեն առկա էջերը պահպանվում են, բացառությամբ վերջին տարվա (`--refresh-years 1`), որի
  պայմանագրերն ու վճարումները փոխվում են ամեն օր. դրա էջերը նորից ներբեռնվում են, եթե 12 ժամից հին են
  (`--max-age-hours`)։ Մանիֆեստը գրվում է յուրաքանչյուր 100 էջից հետո, ուստի ընդհատված գործարկումը շարունակվում է
  կանգառի տեղից. 45 վ-ում (երկու փորձ) չպատասխանած էջը նորից հարցվում է հաջորդ անցման ժամանակ (մինչև երեք անցում).
  `--force`-ը ամեն ինչ նորից ներբեռնում է։
* `build`-ը վերստեղծում է ամբողջ տվյալների բազան (≈1 րոպե) և տպում `qc_summary`. `docs`-ը վերագեներացնում է
  `docs/data_dictionary.md`-ն և `docs/*/inventory.md`-ը։
* Ստուգեք `SELECT * FROM qc_summary` (տես [data_quality.md](data_quality.md)). եթե `missing_translation`-ը `warn` է,
  թարգմանեք նոր անվանումները (տես [translations.md](translations.md)) և վերակառուցեք։
* `release`-ը պահանջում է մաքուր աշխատանքային ծառ և push արված `HEAD` (թողարկման պիտակը դրվում է այդ կոմիտի վրա), ինչպես
  նաև `gh` պահոցում գրելու իրավունքով։ Լռելյայն պիտակը `data-<վերջին հաշվետվության հարցման ամսաթիվը>` է։

Խորհուրդ տրվող հաճախականություն. ամսական. առնվազն մեկ անգամ հունվար–փետրվարին՝ մինչև կայքը կհեռացնի ամենահին տարին
(կայքը պահում է երեք տարի. այս պահոցի թողարկումները ավելի հին տարիների միակ արխիվն են)։

## Երբ հայտնվում է նոր տարի

Կայքը նոր բյուջետային տարին ավելացնում է տարիների ցուցակի վերևում, ուստի մյուս տարիների `SITE_YEAR` ինդեքսները
փոխվում են (`1`-ը միշտ վերջին տարին է)։ Հավաքիչը համապատասխանությունը կարդում է ձևից `catalog`-ի յուրաքանչյուր
գործարկման ժամանակ, ուստի կոդում ոչինչ փոխելու կարիք չկա։ Ամենահին տարին անհետանում է կայքից. պահպանեք նրա հումքային
տվյալները (թողարկումների արխիվները), եթե դրանք պետք են հետագա build-երում — build-ն օգտագործում է միայն `data/raw`-ում և
`data/catalog`-ում եղածը։

Սպասեք շատ նոր անվանումների (ծրագրեր, հաշիվներ, դեֆիցիտի տողեր). թարգմանեք դրանք (տես վերևում)։

## Ինչ անել, եթե…

**Հարցումը ձախողվում է կամ կախվում է։** Սերվերը վերակայում է երկար կապերը և երբեմն պահում է հարցումը առանց պատասխանի։
Հաճախորդը կրկնում է յուրաքանչյուր հարցում (5 փորձ աճող դադարներով), յուրաքանչյուր հարցման համար օգտագործում է նոր կապ
և ունի 120 վ ընթերցման ժամանակի սահմաններ (400 վ արդյունքների էջերի համար՝ `config.HTTP_RESULT_TIMEOUT`)։ Այն հարցումը,
որի արդյունքում ցանց չկա կամ խմբավորումը անսպասելի է, կրկնվում է նոր սեսիայում։ Կրկին գործարկեք քայլը — պայմանագրերի
համար այն շարունակում է այնտեղից, որտեղ ձախողվել էր. հաշվետվությունները միշտ նորից են հարցվում։

**Կոդերը չեն լուծվել** (`qc_unresolved_code`)։ Ստուգիչ հարցումները պիտակի համար կոդ չեն գտել։ Նայեք պիտակին
`stg_report_node`-ում և տարվա դասակարգիչների ցուցակին (`data/catalog/classifiers/<report>_<year>.json`)։ Սովորաբար
կայքը ինչ-որ բան վերանվանել է. այդ տարվա/հաշվետվության համար `fetch`-ը կրկին գործարկելը նորից կատարում է ստուգիչ
հարցումները (մինչև երեք փուլ՝ 5, 20 և 60 առավել նման կոդերով, թեկնածու կոդերի բազմությունը ընդլայնելով)։ Եթե պիտակը
ցուցակում ընդհանրապես համապատասխանություն չունի, տողը մնում է առանց կոդի. գումարները, այնուամենայնիվ, փաստերում են։

**Խմբավորման պիտակները փոխվել են** (`warnings` `data/catalog/site.json`-ում, կամ հարցումը ձախողվում է
`grouping … != …` սխալով)։ Թարմացրեք չափումների `group_value` / `group_label`-ը `src/arm_budget/config.py`-ում։

**Ձևերում հայտնվել է նոր եկամտի տեսակ, դեֆիցիտի դիտում կամ հաշվետվություն։** Տարբերակները գրանցված են
`data/catalog/classifiers/*.json`-ում (`selects`). ավելացրեք դրանք `config.REVENUE.extra` / `config.DEFICIT.extra`-ում
կամ նոր `Report` `config.py`-ում, և համապատասխան վերլուծությունը `build.py`-ում։

**Դեֆիցիտի հաշվետվությունը ստացել է համարակալման նոր ոճ։** Կառուցվածքը ածանցվում է `parsers/deficit.py`-ում
(կանոնավոր արտահայտություններ `Ա.`, `1.`, `1.1`-ի համար). չճանաչված տողերը դառնում են `detail` տողեր։

**Էջի մակետը փոխվել է։** Բոլոր վերլուծիչները (parsers) փոքր են և ծածկված են fixture-ներով թեստերով
(`tests/test_parsers.py`)՝ ցանց (`parsers/grid.py`), ձևեր (`parsers/forms.py`), պայմանագրեր (`parsers/contracts.py`),
արտահանումներ (`parsers/xls_export.py`)։

## Կոդի կառուցվածք

| մոդուլ | դեր |
|---|---|
| `config.py` | ուղիներ, URL, HTTP կարգավորումներ, հաշվետվությունների և դասակարգիչների սահմանումներ |
| `site.py` | կայքի հաճախորդ. սեսիա, ձև, հարցում, արդյունք, արտահանում, պայմանագրեր. կրկնություններ |
| `fetch.py` | `catalog`, `fetch`, `contracts` քայլեր. մանիֆեստներ `data/catalog`-ում |
| `tree.py` | խմբավորված ցանցը դարձնում է հանգույցների ծառ (և պայմանագրային տողերի հարթ ցուցակ) |
| `resolve.py` | դասակարգիչների կոդեր ըստ անվանման և ստուգիչ հարցումների (օգտագործվում է `fetch`-ի և `build`-ի կողմից) |
| `build.py` | կառուցում է DuckDB տվյալների բազան |
| `translations.py`, `translit.py`, `reference.py` | բառարաններ, տառադարձություն, ստատիկ եռալեզու տեղեկատու տվյալներ |
| `docs.py`, `release.py` | գեներացվող փաստաթղթավորում, տվյալների պատկերներ GitHub թողարկումներում |
