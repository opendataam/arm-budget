[English](../en/data_quality.md) | **Հայերեն** | [Русский](../ru/data_quality.md)


## Ստուգումներ

| check | table | what is checked |
|---|---|---|
| `unresolved_code` | `qc_unresolved_code` | ծախսերի ծառի և եկամուտների ծառերի (տեսակներ 1–3) յուրաքանչյուր տող ունի դասակարգիչի կոդ |
| `tree_total` | `qc_tree_total` | յուրաքանչյուր ծառի տերևների գումարը հավասար է կայքում հրապարակված ընդհանուր հանրագումարին (տարեկան պլան և կատարում) |
| `tree_subtotal` | `qc_tree_subtotal` | կայքում հրապարակված յուրաքանչյուր միջանկյալ հանրագումար հավասար է իր ենթատողերի գումարին |
| `revenue_types` | `qc_revenue_types` | հարկեր և տուրքեր + պաշտոնական դրամաշնորհներ + այլ եկամուտներ = ընդհանուր եկամուտներ (`SITE_EBUDG` 1+2+3 ընդդեմ 0) |
| `site_total` | `qc_site_total` | սկզբնական էջի ընտրացանկի հանրագումարները = տվյալների բազայի վերջին տարվա տարեկան պլաններ |
| `balance` | `qc_balance` | ծախսերի պլան − եկամուտների պլան = պլանավորված դեֆիցիտ, յուրաքանչյուր տարվա համար |
| `contract_link` | `qc_contract_link` | պայմանագրեր ունեցող ծախսերի յուրաքանչյուր տող ունի պայմանագրային տվյալներ, և պայմանագրի յուրաքանչյուր էջ պատկանում է որևէ տողի |
| `contract_paid` | `qc_contract_paid` | (տեղեկատվական) տողեր, որոնցում պայմանագրերով վճարումները գերազանցում են տողի կատարված գումարը |
| `missing_translation` | `qc_missing_translation` | յուրաքանչյուր հայերեն անվանում ունի անգլերեն և ռուսերեն թարգմանություն |
| `renamed_code` | `qc_renamed_code` | (տեղեկատվական) կոդեր, որոնց անվանումը տարբեր տարիներին տարբերվում է |

## Աղբյուրի առանձնահատկություններն ու խնդիրները

1. **Արդյունքներում միայն անվանումներ են, առանց կոդերի։** Կոդերը վերցվում են ձևերի նշման վանդակների ցուցակներից. տողերի ≈5 %-ը
   պահանջում է ստուգիչ հարցում (ֆիլտրված հարցում), քանի որ մեկ անվանում ունեն մի քանի կոդեր կամ անվանումը տարբերվում է ցուցակից
   (տե՛ս [sources.md](sources.md#դասակարգիչների-կոդեր-ինչու-են-պետք-ստուգիչ-հարցումները))։
2. **Ցուցակներում առանց անվանման կոդեր։** Տարվա դասակարգիչների ցուցակները պարունակում են դատարկ անվանմամբ մի քանի կոդ
   (ծրագրեր `004077`, `004576`, `004617`, եկամուտների խումբ `1688`, եկամուտների մի քանի հաշիվ), մինչդեռ արդյունքներում
   դրանց անվանումները երևում են (օրինակ՝ «Ուսուցչի օրվա առթիվ … պարգևատրում» ծրագիրը, ադամանդների առևտրի
   պետական տուրքերի եկամուտների խումբը)։ Ստուգիչ հարցումները նախ ստուգում են այս կոդերը. `dim_*` աղյուսակներն անվանումը վերցնում են արդյունքների ցանցից։
3. **Եկամուտների պլաններ «ընդհանուր եկամուտներ» ընտրությամբ։** `SITE_EBUDG = 0` դեպքում կայքը պլաններ ցույց է տալիս միայն
   ընդհանուր հանրագումարի համար. մանրամասն պլանները հրապարակվում են միայն եկամտի տեսակներով, ուստի փաստերը կառուցվում են 1–3 տեսակներից։
4. **Եկամուտների պլանները սահմանվում են տեսակի ամբողջության համար։** Հարկերի և տուրքերի տարեկան պլանի ≈97 %-ը և
   պաշտոնական դրամաշնորհների պլանի 100 %-ը չեն բաշխված բաժինների, խմբերի կամ հաշիվների միջև (այլ եկամուտները բաշխված են
   ամբողջությամբ)։ Build-ը այս մասը պահում է որպես մեկ տող տարվա և տեսակի համար՝ `line_kind = 'unallocated'`
   (`qc_revenue_unallocated`). ուստի շատ հաշիվներ ունեն կատարում առանց պլանի։ Եկամուտների պլանը և կատարումը համեմատեք
   եկամտի տեսակի մակարդակով։
5. **Կետադրություն և ուղղագրություն։** Ցանցը հանում է ստորակետերը, կետ-ստորակետերը և չակերտները. ցուցակները դրանք պահում են, բայց պարունակում են
   փոխադրված տողեր (`\n` բառերի ներսում), լատինական նման տառեր (`u`՝ `ս`-ի փոխարեն) և պատահական վրիպակներ։ Բազայի անվանումները
   մաքրված են տողադարձերից. բնագրային ուղղագրությունը պահպանված է։
6. **Անվանումները փոխվում են տարիների ընթացքում** (վերանվանված նախարարություններ, վերաձևակերպված ծրագրեր), իսկ կոդերը կրկին օգտագործվում են վերանվանված
   մարմինների համար. `dim_*`-ը պահում են վերջին անվանումը, `dim_name`-ը՝ բոլոր անվանումները ըստ տարիների (`qc_renamed_code`)։ Վերանվանված մարմինը
   կարող է նաև նոր կոդ ստանալ (օրինակ՝ Էկոնոմիկայի նախարարությունը՝ `104004` և `104007`)։
7. **Կենդանի տվյալներ։** Ընթացիկ տարին թարմացվում է ամեն օր. րոպեների տարբերությամբ արված հարցումները կարող են թեթևակի տարբերվել։ Պայմանագրերի
   էջերը ներբեռնվում են հաշվետվական հարցումներից հետո, ուստի դրանց վճարումները կարող են մի փոքր ավելի թարմ լինել, քան
   `fact_expenditure`-ը։
8. **Դեֆիցիտի հաշվետվությունը ադիտիվ չէ։** Մանրամասն տողերը իրենց վերևի համարակալված տողի բաշխումներն են
   (մարմիններ, ընկերություններ, վարկեր) և կարող են համընկնել. որոշ պիտակներ պարունակում են հին տարիների մնացորդներ
   («ՀՀ 2017 թվականի պետական բյուջեի տարեսկզբի ազատ մնացորդ» 2024–2026 թվականների հաշվետվություններում)։
9. **Կլորացում։** Ծախսերի և եկամուտների գումարներն ունեն 4 տասնորդական նիշ (հազար դրամ), դեֆիցիտի գումարները և Excel արտահանումները՝
   2 տասնորդական նիշ. կայքի `%` սյունակները կլորացված են ամբողջ թվերի։
10. **Միայն երեք տարի։** Նոր տարի ավելացնելիս կայքը հեռացնում է ամենահին տարին. ավելի հին տվյալներ կան միայն այս պահոցի
    թողարկումներում։
11. **Սերվերի անկայունություն։** Կայքը երբեմն վերականգնում է կապերը կամ երբեք չի պատասխանում հարցմանը. հավաքիչը
    կրկնում է փորձը (տե՛ս [maintenance.md](maintenance.md))։
