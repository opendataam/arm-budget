# Источник: «Интерактивный бюджет» Министерства финансов

[English](../en/sources.md) | [Հայերեն](../hy/sources.md) | **Русский**

## Сайт

<https://budget.minfin.am:82/> — «ՀՀ ՖԻՆԱՆՍՆԵՐԻ ՆԱԽԱՐԱՐՈՒԹՅՈՒՆ · ԻՆՏԵՐԱԿՏԻՎ ԲՅՈՒՋԵ» (Министерство финансов
Республики Армения, Интерактивный бюджет). Веб-интерфейс казначейской системы (LSFinance компании LSoft), который
показывает план и исполнение **государственного бюджета** текущего и двух предыдущих лет. Интерфейс существует
только на армянском языке.

В левом меню «ԲՅՈՒՋԵ» перечислены три отчета с годовым планом последнего года:

| пункт меню | страница | отчет | база данных |
|---|---|---|---|
| Ծախսեր (расходы) | `site_b` | расходы по функциональной, программной, ведомственной и экономической классификации; контракты | `fact_expenditure`, `fact_contract` |
| Եկամուտներ (доходы) | `site_d` | доходы по виду доходов, разделу, группе, ведомству и казначейскому счету | `fact_revenue` |
| Դեֆիցիտ (дефицит) | `site_l` | источники финансирования дефицита | `fact_deficit` |

Годы: форма предлагает только **последние три года** (на момент написания 2024–2026). Более ранние годы на сайте
недоступны. Текущий год обновляется непрерывно (экспорт расходов от 5 ноября 2026 г. имел пометку
«առ 04/11/26», то есть данные на предыдущий день); завершенные годы приведены на конец декабря.

## Единицы и столбцы

Все суммы указаны в **тыс. драмов** («հազ. դրամներով»). Каждый результат содержит одни и те же 12 столбцов со значениями:

| заголовок | значение | столбец в базе данных |
|---|---|---|
| 1 եռամս. պլան / Գումարը / % | план за I квартал, исполнено, % | `q1_plan_kamd`, `q1_actual_kamd` |
| Կիսամ. պլան / Գումարը / % | план за январь–июнь, исполнено, % | `h1_plan_kamd`, `h1_actual_kamd` |
| 9 ամիս պլան / Գումարը / % | план за январь–сентябрь, исполнено, % | `m9_plan_kamd`, `m9_actual_kamd` |
| Տարի պլան / Գումարը / % | годовой план, исполнено с 1 января, % | `year_plan_kamd`, `year_actual_kamd` |

* Планы и исполненные суммы приводятся **нарастающим итогом** с 1 января (I полугодие включает I квартал).
* Для текущего года исполненная сумма за еще не закончившийся период — это исполнение **на дату «по состоянию на»**
  (`meta_year.as_of_date`); поэтому столбец «год» показывает исполнение с начала года.
* Столбцы `%` в таблицах фактов не хранятся (это `actual / plan`); они сохранены в `raw_grid_cell`.
* План — это план казначейской системы (утвержденный бюджет с изменениями, внесенными в течение года).
* Таблицы расходов и доходов дают суммы с 4 знаками после запятой, таблица дефицита и экспорты Excel — с 2.

## Как работает сайт

Сайт — одностраничное приложение ([w2ui](https://w2ui.com/)) с серверными сессиями:

1. `GET /` создает сессию: страница содержит скрытое поле `sessid` и устанавливает cookie `bcsession`. Пункты меню
   содержат годовые планы последнего года (`meta_site_total`).
2. `GET /param.php?sessid=…&lang=1&custid=0&page=site_b&isdoc=0` возвращает **форму** отчета.
3. Форма отправляется как `POST /param.php` с `ACTION=VIEW` и:
   * `SITE_YEAR` — индекс: `1` = последний год, `2` = предыдущий, … (соответствие меняется при добавлении нового
     года; оно хранится в `data/catalog/site.json` и `meta_year.year_index`);
   * фильтры — списки флажков `mid[]` (ведомство), `grp[]`, `sgrp[]`, `cls[]`, `prog[]`, `sub[]`, `acc[]`;
     нет значения = всё; списки в ответе сужаются до кодов, совместимых с фильтром;
   * группировка — выпадающие списки `site_NN1` … `site_NN7` («Դասավորել ըստ դասակարգման», порядок классификаторов);
   * вид доходов `SITE_EBUDG` (доходы) или представление `SITE_DALL` (дефицит).
   Сервер сохраняет запрос в сессии. После выбора года списки флажков содержат **классификаторы этого года с их
   кодами** — это единственное место, где сайт показывает коды.
4. `GET /Popup.php?page=SITE_BG&uid=1&data=.&sessid=…` (расходы; `SITE_DG` для доходов) возвращает
   **результат** сохраненного запроса в виде таблицы w2ui: JavaScript-литерал с заголовками столбцов и записями.
   Форма дефицита возвращает свою таблицу сразу в ответе на шаг 3.
5. `GET /xml/xmlopen.php?page=SITE_B_XLS&uid=1&lang=1` (`SITE_D_XLS`, `SITE_L_XLS`) записывает экспорт последнего
   результата в Excel (XML Spreadsheet 2003) в `xml/temp/<id>.xls` и возвращает ссылку на него. Его заголовок
   содержит дату, на которую приведены данные: «ԲՅՈՒՋԵ ԾԱԽՍԵՐ առ 04/11/26 - հազ. դրամներով».
6. `GET /Popup.php?page=SITE_C&uid=1&data=<PARAM>{line};{year index};</PARAM>` возвращает **контракты** строки
   расходов (идентификатор строки — столбец `c20` результата, сгруппированного по «Պայմանագրեր»).

Сборщик использует одну сессию за раз, выдерживает 0,5 с между запросами, не переиспользует соединения (сервер
молча обрывает простаивающие keep-alive-соединения, и запрос, отправленный по такому соединению, зависает) и
повторяет неудавшиеся запросы. Полное дерево расходов формируется от 30 с до 5 минут.

## Отчеты

### Расходы (`site_b`)

Классификаторы (списки флажков и варианты «группировать по»):

| список | вариант группировки | классификатор | коды | таблица |
|---|---|---|---|---|
| `grp[]` | 1 Բաժին | функциональный раздел | 2 цифры | `dim_functional` (уровень 1) |
| `sgrp[]` | 2 Խումբ | функциональная группа | 4 цифры | `dim_functional` (уровень 2) |
| `cls[]` | 3 Դաս | функциональный класс | 6 цифр | `dim_functional` (уровень 3) |
| `prog[]` | 4 Ծրագիր | программа/мероприятие | 6 цифр | `dim_program` |
| `mid[]` | 5 Գերատեսչական դասակարգում | ведомство | 6 цифр | `dim_department` |
| `sub[]` | 6 Հոդված | статья экономической классификации | 4 цифры | `dim_economic` |
| — | 7 Պայմանագրեր | контракты (идентификатор строки) | — | `fact_contract` |

Запрос, **сгруппированный по всем шести классификаторам**, возвращает самые детальные данные, которые публикует
сайт, в виде **дерева** в порядке обхода в глубину: общий итог, затем раздел → группа → класс → программа →
ведомство → статья; каждая строка содержит подпись только своего уровня, элементы одного уровня отсортированы по
коду. Строки последнего уровня — это бюджетные строки (`fact_expenditure`), остальные — промежуточные итоги
(`stg_report_node`).

Запрос, сгруппированный по **контрактам**, возвращает плоский список строк, у которых есть контракты, с
шестью подписями каждой и идентификатором строки; это связывает `fact_expenditure.contract_line_id` со страницами
контрактов.

Список программ («Ֆունկցիոնալ դասակարգման ծրագիր») содержит 6-значные коды казначейской системы (например,
`004828`); названия — это названия программных мероприятий закона о бюджете.

В форме даны ссылки на два PDF с методическими указаниями (приложения 16 и 17 к приказу министра финансов и
экономики от 9 января 2007 г. N 5-Ն): экономическая классификация текущих расходов (класс 400000) и расходов на
нефинансовые активы (класс 500000). Из них взяты верхние уровни экономической классификации в
`dim_economic_level`.

### Доходы (`site_d`)

| список | вариант группировки | классификатор | коды | таблица |
|---|---|---|---|---|
| `grp[]` | 1 Բաժին | раздел доходов (НДС с юридических лиц, акцизный налог на импорт, …) | 2 цифры | `dim_revenue_section` |
| `sgrp[]` | 2 Խումբ | группа доходов | 4 цифры | `dim_revenue_group` |
| `mid[]` | 3 Գերատեսչական դասակարգում | ведомство, администрирующее доход | 6 цифр | `dim_department` |
| `acc[]` | 4 Հաշիվ | казначейский счет доходов | 12 цифр | `dim_revenue_account` |

`SITE_EBUDG` («ԵԿԱՄՈՒՏՆԵՐԻ ՏԵՍԱԿՆԵՐ») выбирает вид доходов: `0` — все доходы, `1` — налоги и пошлины,
`2` — официальные трансферты, `3` — прочие доходы. **Важная особенность:** при `0` план указан только в общем итоге,
во всех детальных строках план равен 0; планы детальных строк публикуются только по видам. Поэтому сборщик
выполняет запросы по всем четырем; факты строятся по видам 1–3 (`fact_revenue.revenue_type`), вид 0 сохраняется для
проверки того, что виды в сумме дают итог (`qc_revenue_types`).

**Бо́льшая часть плана доходов не распределена по счетам.** Даже по видам ≈97 % годового плана налогов и пошлин и
весь план официальных грантов заданы только на уровне вида дохода (общий итог результата); планы счетов покрывают
остальное. Исполнение всегда отражается по счетам. Сборка сохраняет разницу одной строкой на год и вид с
`line_kind = 'unallocated'` (без кодов), чтобы суммы по `fact_revenue` совпадали с опубликованными итогами
(`qc_revenue_unallocated`). Сравнивайте план и исполнение доходов на уровне вида дохода, а не по счетам.

В форме дана ссылка на приложение 19 к тому же приказу (текущие доходы, класс 700000).

### Дефицит (`site_l`)

`SITE_DALL` («ՏԵՍԱԿ»): `1` — только итоги (≈20 строк), `2` — все строки (≈80–100). Отчет представляет собой
оформленный отчет об источниках финансирования дефицита: итог, А. внутренние источники, Б. внешние источники,
пронумерованные позиции (1., 1.1) и ненумерованные детальные строки (органы, компании, займы), вводимые словами
«այդ թվում» (в том числе) или «որից» (из них). Отрицательные значения показаны в скобках. Сборщик сохраняет все
строки (`fact_deficit`) со структурой, выведенной из нумерации (`item_code`, `row_kind`, `parent_line_no`); см.
[database.md](database.md).

### Контракты (`SITE_C`)

Для каждой строки расходов с контрактами: контрагент («Գործընկեր»), даты начала и окончания контракта, сумма
контракта и сумма, выплаченная по этой строке (тыс. драмов), и ссылки на документы — контракт в системе
электронных закупок `armeps.am` и сканы, хранящиеся на сайте (`xml/storage/*.pdf`). Сами документы не скачиваются
(`fact_contract_file` хранит ссылки). Контракт, оплачиваемый по нескольким строкам, встречается по одному разу для
каждой строки.

## Коды классификаторов: зачем нужны пробные запросы

Таблицы результатов содержат **только названия, но не коды**. Коды берутся из списков флажков формы за тот же год.
Сопоставление выполняется только по буквам и цифрам, поскольку таблица отбрасывает запятые и другие знаки
препинания («Օրենսդիր և գործադիր մարմիններ, պետական կառավարում» в списке против «… մարմիններ պետական կառավարում» в
таблице) и добавляет к статьям экономической классификации префикс «- ».

Сопоставление по названию разрешает ~95 % строк. Остальные — это названия, общие для нескольких кодов (пять
ведомств с названием «Այլ մարմիններ», статьи экономической классификации 4221/4229 с одинаковым названием
«Գործուղումների և շրջագայությունների ծախսեր», старые и новые коды переименованного министерства) или подписи,
не совпадающие ни с одним названием из списков (опечатки, иная формулировка). Для них сборщик выполняет **пробный
запрос**: тот же запрос, отфильтрованный по одному коду-кандидату (`mid[]=301022`, …). В результате пробного
запроса каждая строка этого уровня классификатора имеет данный код; она сопоставляется со строкой полного дерева с
теми же подписями на пути и теми же суммами. Пробные запросы хранятся в `data/raw/probes` и перечислены в
`meta_probe`; метод, использованный для каждой строки, указан в `stg_report_node.code_method`. После пробных запросов
все коды строк фактов определены (`qc_unresolved_code`).

## Сырые данные на диске

| путь | содержимое |
|---|---|
| `data/catalog/site.json` | итоги меню, годы и их индексы `SITE_YEAR` |
| `data/catalog/classifiers/<report>_<year>.json` | форма отчета за год: списки классификаторов (код, название), параметры |
| `data/catalog/requests.json` | каждый запрос отчета: параметры, файл, строки, хеш содержимого, дата «по состоянию на» |
| `data/catalog/probes.json` | каждый пробный запрос |
| `data/catalog/contracts/<year>.csv` | строки расходов с контрактами, число контрактов, хеш содержимого |
| `data/catalog/documents.json` | документы PDF |
| `data/raw/site/` | стартовая страница, страницы форм по отчетам и годам (HTML в gzip) |
| `data/raw/reports/<year>/` | страницы результатов (`*.html.gz`) и экспорты Excel (`*.export.xml.gz`) |
| `data/raw/probes/<year>/<request>/` | результаты пробных запросов |
| `data/raw/contracts/<year>/<line>.html.gz` | страницы контрактов |
| `data/raw/documents/` | методические указания в PDF |

Манифесты в `data/catalog` версионируются в git (`content_sha256` не зависит от идентификатора сессии, поэтому
git diff показывает реальные изменения данных); `data/raw` публикуется в релизах.
